## What is an agent?

An agent is a configured AI entity that runs on behalf of your organization. It combines a language model, a voice (for voice agents), a transcriber (for voice agents), and a set of instructions to handle real-world interactions with prospects.

Every agent encapsulates:

- **Prompt template** - the system prompt governing behavior and persona
- **LLM config** - which model to use, sampling parameters, and fallbacks
- **Transcriber config** - how speech is converted to text (voice agents only)
- **Voice config** - which TTS voice the agent speaks in (voice agents only)
- **Greeting and goodbye** - how the agent opens and closes interactions
- **Interruption settings** - how aggressively the agent yields to the human
- **VAD config** - voice activity detection parameters
- **Tools** - external functions the agent can call during a session

## LLM configuration

The `llm_config` block controls which language model powers the agent and how it generates responses.

```json
{
  "provider": "openai",
  "model": "gpt-4o",
  "temperature": 0.7,
  "max_tokens": 200,
  "top_p": 0.95,
  "presence_penalty": 0.1,
  "parallel_tool_calls": true,
  "system_prompt": "Additional system-level instructions appended to the prompt template.",
  "fallbacks": [
    {
      "provider": "anthropic",
      "model": "claude-3-5-sonnet-20241022",
      "temperature": 0.7,
      "max_tokens": 200
    },
    {
      "provider": "groq",
      "model": "llama-3.3-70b-versatile"
    }
  ]
}
```

<ResponseField name="provider" type="string" required>
  LLM provider. Supported values: `openai`, `anthropic`, `google`, `groq`, `azure-openai`, `cerebras`, `togetherai`, `xai`, `mistral`, `openrouter`.
</ResponseField>

<ResponseField name="model" type="string" required>
  Model identifier for the chosen provider. See provider-specific notes below.
</ResponseField>

<ResponseField name="temperature" type="number">
  Sampling temperature between `0` and `2`. Lower values produce more focused, deterministic responses. Higher values produce more varied output. Default: `0.7`.
</ResponseField>

<ResponseField name="max_tokens" type="integer">
  Maximum number of tokens to generate per turn. For voice agents, keep this low (150-250) so responses remain concise and conversation feels natural. Minimum: `1`.
</ResponseField>

<ResponseField name="top_p" type="number">
  Nucleus sampling parameter. The model considers tokens in the top `top_p` probability mass. Range: `0` to `1`.
</ResponseField>

<ResponseField name="top_k" type="integer">
  Top-k sampling. **Anthropic models only.** Limits sampling to the top k tokens at each step.
</ResponseField>

<ResponseField name="presence_penalty" type="number">
  Penalizes tokens that have already appeared in the conversation to reduce repetition. **OpenAI models only.** Range: `-2.0` to `2.0`.
</ResponseField>

<ResponseField name="parallel_tool_calls" type="boolean">
  Allow the model to invoke multiple tools in a single turn. Useful when an agent needs to look up multiple data points simultaneously. Default: `false`.
</ResponseField>

<ResponseField name="system_prompt" type="string">
  Additional system-level text appended after the `prompt_template`. Use this for boilerplate instructions (e.g. compliance disclaimers) that apply across multiple agents.
</ResponseField>

<ResponseField name="fallbacks" type="array">
  Ordered list of fallback LLM configs. When the primary provider returns an error or is unavailable, Nova tries each fallback in sequence until one succeeds. Each item has the same shape as the primary config (`provider`, `model`, `temperature`, etc.).
</ResponseField>

### Fallback LLM strategy

Configure fallbacks so your agent remains operational even when a primary provider experiences an outage:

```json
{
  "provider": "openai",
  "model": "gpt-4o",
  "temperature": 0.7,
  "max_tokens": 200,
  "fallbacks": [
    {
      "provider": "anthropic",
      "model": "claude-3-5-sonnet-20241022",
      "temperature": 0.7,
      "max_tokens": 200
    },
    {
      "provider": "groq",
      "model": "llama-3.3-70b-versatile",
      "temperature": 0.7,
      "max_tokens": 200
    }
  ]
}
```

Nova tries each fallback in order. If all providers fail, the session returns an error.

<Tip>
  For production voice agents, always configure at least one fallback. A two-provider setup (e.g. OpenAI primary, Groq fallback) significantly improves reliability.
</Tip>

## Transcriber configuration

For voice agents, the transcriber converts the prospect's speech to text in real time. The transcription feeds directly into the LLM turn.

```json
{
  "provider": "deepgram",
  "model": "nova-3",
  "language": "en-US",
  "endpointing_ms": 300,
  "smart_format": true,
  "keywords": ["Acme", "CRM", "ARR", "SaaS"],
  "fallbacks": [
    {
      "provider": "openai",
      "model": "whisper-1",
      "language": "en"
    }
  ]
}
```

<ResponseField name="provider" type="string" required>
  STT provider. Supported values: `deepgram`, `elevenlabs`, `speechmatics`, `openai`, `groq`, `sarvam`, `assemblyai`, `azure`, `gladia`, `google`, `cartesia`, `soniox`.
</ResponseField>

<ResponseField name="model" type="string">
  Provider-specific model identifier. For Deepgram: `flux`, `nova-3`, `nova-3-general`, `nova-3-medical`, `nova-2`, `nova-2-general`, `nova-2-phonecall`, and more. For OpenAI: `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `whisper-1`. For Groq: `whisper-large-v3`, `whisper-large-v3-turbo`. For ElevenLabs: `scribe-v2-realtime`. For Sarvam: `saaras-3`. For AssemblyAI: `universal-streaming-english`, `universal-streaming-multilingual`, `u3-rt-pro`. For Google: `chirp-2`, `chirp-3`. For Cartesia: `ink-whisper`. For Speechmatics: `enhanced`, `standard`. For Soniox: `stt-rt-v4`.
</ResponseField>

<ResponseField name="language" type="string">
  BCP-47 language code (e.g. `en-US`, `es-ES`, `ar`, `hi-IN`). Omit to use the provider's auto-detect.
</ResponseField>

<ResponseField name="endpointing_ms" type="integer">
  Milliseconds of silence after which the transcriber commits the current speech segment and sends it to the LLM. Lower values make the agent more responsive but can cut off slow speakers. Recommended range: `200`-`400`. Default: `300`.
</ResponseField>

<ResponseField name="smart_format" type="boolean">
  Enable provider-specific post-processing to format numbers, dates, currency, and punctuation. Deepgram only. Default: `false`.
</ResponseField>

<ResponseField name="keywords" type="array">
  List of domain-specific terms to boost recognition accuracy. Useful for product names, technical jargon, or names that are commonly misheard.
</ResponseField>

<ResponseField name="fallbacks" type="array">
  Ordered list of fallback transcriber configs. Nova tries each in sequence if the primary fails.
</ResponseField>

```json
{
  "provider": "elevenlabs",
  "voice_id": "21m00Tcm4TlvDq8ikWAM",
  "model": "eleven_turbo_v2_5",
  "language": "en",
  "emotion": "friendly"
}
```

<ResponseField name="provider" type="string" required>
  TTS provider. Supported values: `elevenlabs`, `cartesia`, `openai`, `cambai`, `sarvam`, `inworld`, `minimax`, `mistral`.
</ResponseField>

<ResponseField name="voice_id" type="string" required>
  Provider-specific voice identifier. Use the `/voices` endpoint to browse available voices for each provider.
</ResponseField>

<ResponseField name="language" type="string">

<ResponseField name="emotion" type="string">

</ResponseField>

## Greeting configuration

Controls how the agent opens an interaction.

```json
{
  "agent_speaks_first": true,
  "greeting": "Hi, is this {{prospect_name}}? Great, this is Alex from Acme Corp - do you have two minutes?",
  "pause_before_first_message": 800,
  "voice_mail_message": "Hi {{prospect_name}}, this is Alex from Acme Corp. I'll try you again soon. Have a great day!",
  "welcome_message_is_generated": false
}
```

<ResponseField name="agent_speaks_first" type="boolean">
  If `true`, the agent delivers the greeting immediately after the call connects without waiting for the prospect to speak. Set to `false` for inbound calls where the prospect speaks first.
</ResponseField>

<ResponseField name="greeting" type="string">
  Static opening message. Supports template variables (`{{prospect_name}}`, `{{prospect_first_name}}`, etc.) resolved from the prospect record at runtime.
</ResponseField>

<ResponseField name="welcome_message_is_generated" type="boolean">
  If `true`, the LLM generates the opening message dynamically instead of using the static `greeting` string. Useful when you want the agent to personalize the opener based on prospect context.
</ResponseField>

<ResponseField name="pause_before_first_message" type="integer">
  Milliseconds to wait after the call connects before the agent speaks. Helps avoid the agent speaking before the prospect has had a chance to say "Hello". Recommended: `500`-`1200`. Default: `1000`.
</ResponseField>

<ResponseField name="voice_mail_message" type="string">
  Message left when voicemail is detected. Keep it brief (under 30 seconds of audio). Supports the same template variables as `greeting`.
</ResponseField>

## Extra config / Interruption settings

The `extra_config` block controls how the agent handles interruptions and turn-taking.

```json
{
  "allow_interruptions": true,
  "interruption_sensitivity": 0.6,
  "min_words": 2,
  "turn_detector": "server_vad",
  "response_delay_ms": 100
}
```

<ResponseField name="allow_interruptions" type="boolean">
  If `true`, the prospect can interrupt the agent mid-utterance and the agent will yield. Set to `false` for compliance scenarios where the agent must complete its full statement. Default: `true`.
</ResponseField>

<ResponseField name="interruption_sensitivity" type="number">
  How sensitive the agent is to being interrupted. Range: `0` (requires very clear intent to interrupt) to `1` (yields on any sound). Default: `0.5`. Higher values make conversations feel more natural but can cause false interruptions from background noise.
</ResponseField>

<ResponseField name="min_words" type="integer">
  Minimum number of words the prospect must say before an interruption is recognized. Prevents brief affirmations like "mm-hmm" from interrupting the agent. Default: `2`.
</ResponseField>

<ResponseField name="turn_detector" type="string">
  Algorithm used to detect turn boundaries. Options: `server_vad` (voice activity detection), `silence_based`. Default: `server_vad`.
</ResponseField>

<ResponseField name="response_delay_ms" type="integer">
  Milliseconds of silence after the prospect stops speaking before the agent responds. A small delay (100-300ms) makes conversations feel more natural. Default: `100`.
</ResponseField>

## VAD configuration

Voice activity detection determines when the prospect is speaking versus silent.

```json
{
  "activation_threshold": 0.5,
  "min_silence_duration": 300,
  "min_speech_duration": 100,
  "sample_rate": 16000
}
```

<ResponseField name="activation_threshold" type="number">
  Confidence threshold above which audio is classified as speech. Range: `0` to `1`. Lower values detect quieter speech but increase false positives from background noise. Default: `0.5`.
</ResponseField>

<ResponseField name="min_silence_duration" type="integer">
  Milliseconds of silence required to consider a speech segment ended. Default: `300`.
</ResponseField>

<ResponseField name="min_speech_duration" type="integer">
  Minimum milliseconds of continuous speech required to trigger VAD activation. Filters out brief clicks and noise. Default: `100`.
</ResponseField>

<ResponseField name="sample_rate" type="integer">
  Audio sample rate in Hz. Default: `16000`. Most telephony uses `8000` Hz; increase for higher quality channels.
</ResponseField>

```json
  }
}
```

<ResponseField name="tool_id" type="string" required>
  ID of the tool to attach. Tools are defined separately and can be reused across agents.
</ResponseField>

<ResponseField name="is_enabled" type="boolean">

</ResponseField>

<ResponseField name="config_override" type="object">
  Per-agent overrides for the tool's base configuration. Useful when the same tool is attached to multiple agents but needs different endpoints or timeouts.
</ResponseField>

## Best practices

### Prompt writing tips

**Be specific about persona and role.** Vague prompts produce inconsistent agents. Give the agent a name, a company, a clear objective, and behavioral constraints.

```
Good: "You are Maya, a support specialist at TechCorp. You help customers troubleshoot login issues. Always verify the customer's email before discussing account details. Do not discuss pricing."

Avoid: "You are a helpful assistant."
```

**Use template variables.** Personalize interactions by referencing prospect data:

- `{{prospect_name}}` - full name
- `{{prospect_first_name}}` - first name only
- `{{prospect_phone}}` - phone number

These are resolved from the prospect record at runtime.

**Optimize for the medium.** Voice prompts should instruct the agent to keep responses short, ask one question at a time, and avoid lists or formatting (which do not translate to speech).

**Include explicit call objectives.** List what the agent should achieve in priority order. The LLM performs better with clear success criteria.

### Model selection guide

| Use case | Recommended model |
|----------|-------------------|
| Sales / SDR calls | `gpt-4.1` or `claude-sonnet-4` |
| High-volume, simple scripts | `gpt-4o-mini` or `groq/llama-3.3-70b-versatile` |
| Multi-step reasoning, complex objection handling | `claude-sonnet-4` or `gpt-4.1` |
| Lowest possible latency | `cerebras/llama-3.1-8b` or `cartesia` TTS |
| Multilingual campaigns | `google/gemini-2.5-flash` + `elevenlabs` multilingual |
| Cost-optimized fallback | `groq/llama-3.1-8b-instant` |
| Enterprise / compliance | `azure-openai/gpt-4.1` |
| Advanced reasoning | `claude-opus-4` or `xai/grok-4-20-reasoning` |

### Voice selection tips

- Match the voice accent and language to your target market. An American-English voice for a market where prospects speak British English creates friction.
- Preview voices using the `/voices` endpoint before committing.
- ElevenLabs `eleven-flash-v2.5` is the best balance of quality and latency for most voice agents.
- For non-English markets, use `eleven-multilingual-v2` (ElevenLabs), Sarvam `bulbul-v3` (Indian languages), or MiniMax `speech-2.8-hd` (multilingual).

### LLM fallback strategy for production

Always configure at least two providers. A recommended production setup:

```json
{
  "provider": "openai",
  "model": "gpt-4.1",
  "fallbacks": [
    {
      "provider": "anthropic",
      "model": "claude-sonnet-4"
    },
    {
      "provider": "groq",
      "model": "llama-3.3-70b-versatile"
    }
  ]
}
```

This gives you coverage for OpenAI outages (use Anthropic) and for Anthropic slowdowns (use Groq's very low latency).

## Common patterns

### A/B testing agents

Clone the production agent, modify one variable (prompt, voice, or temperature), and split traffic across workflows:

```python
# Create B variant
b_agent = requests.post(
    "https://v2-nova-api.prod.czmx.in/api/org/{org_id}/agents",
    headers={"X-API-Key": "YOUR_API_KEY"},
    json={
        "name": "Sales Agent - Opener B",
        "copy_from_agent_id": "agt_production",
        "prompt_template": "Alternate opening that leads with value prop first...",
    },
).json()

# Randomly assign agents when creating sessions
import random
agent_id = "agt_production" if random.random() < 0.5 else b_agent["id"]
```

Track conversion rates per `agent_id` in the `call.completed` webhook payload to determine the winner.

### Per-campaign configuration

Create agent variants for different campaigns rather than modifying the base agent:

```python
def create_campaign_agent(base_agent_id: str, campaign_name: str, custom_prompt_suffix: str):
    return requests.post(
        "https://v2-nova-api.prod.czmx.in/api/org/{org_id}/agents",
        headers={"X-API-Key": "YOUR_API_KEY"},
        json={
            "name": f"Sales Agent - {campaign_name}",
            "copy_from_agent_id": base_agent_id,
            "prompt_template": BASE_PROMPT + "\n\n" + custom_prompt_suffix,
        },
    ).json()

q2_agent = create_campaign_agent(
    base_agent_id="agt_base",
    campaign_name="Q2 Outreach",
    custom_prompt_suffix="Focus on our new Q2 pricing promotion: 20% off annual plans.",
)
```

This keeps your base configuration clean and makes per-campaign rollbacks straightforward.
