## What is a call?

A call is a voice interaction that occurs within an agent session. When a workflow run triggers a voice session, Nova dials the prospect's phone number (outbound) or routes an incoming call to the configured agent (inbound). The resulting call record captures everything that happened: the full transcript, AI-generated summary, post-call evaluations, tool invocations, and cost data.

<Info>
  Calls are created automatically when a voice agent session places or receives a call. You cannot create calls directly via the API.
</Info>

Calls are linked to sessions via `session_id` and to workflow runs via `workflow_run_id`. Most post-call processing - CRM updates, scheduling follow-ups, alerting - is driven by the call record and its evaluations.

## Call directions

| Direction | Description |
|-----------|-------------|
| `outbound` | Agent places a call to the prospect's phone number |
| `inbound` | Prospect calls in and the agent handles the call |

## Call lifecycle

Calls move through a linear lifecycle from the moment Nova dials to final analysis:

```
Dialing -> Connected -> In Progress -> Ended -> Analyzed (FINISHED)
                                              -> Analysis failed (ANALYSIS_FAILED)
        -> Not answered (NO_ANSWER)
        -> Busy (BUSY)
        -> Failed (FAILED / FAILED_SIP / FAILED_VALIDATION)
        -> Cancelled (CANCELLED)
```

| Status | Description |
|--------|-------------|
| `FINISHED` | Call completed and post-call analysis succeeded |
| `FAILED` | Technical failure during the call (media, WebRTC, connectivity) |
| `FAILED_VALIDATION` | Call failed a pre-call validation check - check agent and prospect config |
| `FAILED_SIP` | SIP/trunk-level connection error at the carrier |
| `ANALYSIS_FAILED` | Call completed but post-call analysis (summary, evaluations) failed - audio and transcript are still available |
| `NO_ANSWER` | Prospect did not answer |
| `BUSY` | Prospect's line was busy |
| `CANCELLED` | Call was cancelled before connecting |

```go Go
package main

import (
    "encoding/json"
    "fmt"
    "net/http"
    "strconv"
)

const (
    orgID  = "your-org-id"
    apiKey = "YOUR_API_KEY"
    base   = "https://v2-nova-api.prod.czmx.in/api"
)

type CallList struct {
    Data []map[string]interface{} `json:"data"`
    Meta struct {
        Page       int `json:"page"`
        TotalPages int `json:"total_pages"`
    } `json:"meta"`
}

func ListCalls(status string, page int) (*CallList, error) {
    url := fmt.Sprintf("%s/org/%s/calls?page=%d&size=50", base, orgID, page)
    if status != "" {
        url += "&status=" + status
    }

    req, _ := http.NewRequest("GET", url, nil)
    req.Header.Set("X-API-Key", apiKey)

    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return nil, err
    }
    defer resp.Body.Close()

    var result CallList
    json.NewDecoder(resp.Body).Decode(&result)
    return &result, nil
}

func GetAllCalls(status string) ([]map[string]interface{}, error) {
    var all []map[string]interface{}
    page := 1
    for {
        data, err := ListCalls(status, page)
        if err != nil {
            return nil, err
        }
        all = append(all, data.Data...)
        if page >= data.Meta.TotalPages {
            break
        }
        page++
    }
    return all, nil
}
```

### Filtering by evaluation outcome

To find all calls where a specific evaluation outcome was `true` (for example, all calls where the prospect was interested), fetch calls and filter client-side using the evaluation key:

```python Python
def find_calls_with_evaluation(evaluation_key: str, result: bool = True):
    """Return all calls where evaluation_key matches the expected result."""
    matches = []
    for call in get_all_calls(status="FINISHED"):
        # Fetch full call detail to get evaluations
        detail = requests.get(
            f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/calls/{call['id']}",
            headers={"X-API-Key": API_KEY},
        ).json()
        for ev in detail.get("evaluations", []):
            if ev["outcome_key"] == evaluation_key and ev["result_boolean"] == result:
                matches.append(detail)
                break
    return matches

# Find all calls where INTERESTED = true
interested_calls = find_calls_with_evaluation("INTERESTED", True)
print(f"Found {len(interested_calls)} interested prospects")
```

## Response field reference

<ResponseField name="id" type="string">
  Unique call identifier (e.g. `call_17546d2d`).
</ResponseField>

<ResponseField name="direction" type="string">
  `outbound` or `inbound`.
</ResponseField>

<ResponseField name="status" type="string">
  Terminal call status. See [Call lifecycle](#call-lifecycle) above.
</ResponseField>

<ResponseField name="call_type" type="string">
  How the call was initiated: `workflow` (via a workflow run) or `direct` (via a session start).
</ResponseField>

<ResponseField name="duration_seconds" type="integer">
  Total connected call duration in seconds (from answer to hangup). `0` for unanswered calls.
</ResponseField>

<ResponseField name="from_number" type="string">
  The E.164 phone number the call was placed from (your provisioned number).
</ResponseField>

<ResponseField name="to_number" type="string">
  The E.164 phone number that was dialed (the prospect's number).
</ResponseField>

<ResponseField name="summary" type="string">
  AI-generated summary of the call conversation. `null` if analysis has not yet completed.
</ResponseField>

<ResponseField name="transcript_text" type="string">
  Full plain-text transcript of the call, with speaker labels (e.g. `Agent:`, `Prospect:`). `null` if transcription is not yet available.
</ResponseField>

<ResponseField name="recording_url" type="string">
  Presigned URL to the call recording audio file (MP3). Available a few seconds after the call ends. URLs expire after 24 hours - store recordings in your own storage if you need long-term access.
</ResponseField>

<ResponseField name="evaluations" type="array">
  Post-call evaluation results. Each entry corresponds to an outcome definition configured on your workflow.
  <Expandable title="Evaluation object fields">
    <ResponseField name="outcome_key" type="string">
      The evaluation key matching your outcome definition (e.g. `INTERESTED`, `CALLBACK_REQUESTED`, `SENTIMENT`, `SUMMARY`).
    </ResponseField>
    <ResponseField name="extracted_value" type="string">
      The raw value extracted from the call for this evaluation (e.g. `"positive"`, `"yes"`, `"2026-04-25"`).
    </ResponseField>
    <ResponseField name="reasoning" type="string">
      AI-generated explanation for the evaluation result. Use this to understand why a particular outcome was determined.
    </ResponseField>
    <ResponseField name="result_boolean" type="boolean">
      Boolean outcome of the evaluation. For most evaluations: `true` means the outcome occurred, `false` means it did not.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="tool_logs" type="array">
  Ordered log of every tool the agent invoked during the call.
  <Expandable title="Tool log object fields">
    <ResponseField name="tool_name" type="string">
      Name of the tool that was called (matches the tool definition in your agent config).
    </ResponseField>
    <ResponseField name="status" type="string">
      `success` or `error`.
    </ResponseField>
    <ResponseField name="arguments" type="object">
      The arguments passed to the tool by the agent.
    </ResponseField>
    <ResponseField name="result" type="object">
      The response returned by the tool endpoint. `null` on error.
    </ResponseField>
    <ResponseField name="error_message" type="string">
      Error message if the tool call failed. `null` on success.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the tool was invoked during the call.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="cost_usd" type="string">
  Total cost of the call in USD as a decimal string (e.g. `"0.042"`). This is the sum of LLM token costs, STT processing, and TTS synthesis.
</ResponseField>

<ResponseField name="tokens_input" type="integer">
  Total LLM input tokens consumed during the call (includes system prompt, conversation history, and tool results).
</ResponseField>

<ResponseField name="tokens_output" type="integer">
  Total LLM output tokens generated during the call (the agent's responses).
</ResponseField>

<ResponseField name="tts_characters" type="integer">
  Number of characters synthesized by the text-to-speech provider. Used to calculate TTS cost.
</ResponseField>

<ResponseField name="stt_duration_seconds" type="integer">
  Total audio duration processed by the speech-to-text provider in seconds. Used to calculate STT cost.
</ResponseField>

<ResponseField name="session_id" type="string">
  UUID of the session this call belongs to.
</ResponseField>

<ResponseField name="workflow_run_id" type="string">
  ID of the workflow run that triggered this call. `null` for calls started directly via session API.
</ResponseField>

<ResponseField name="started_at" type="string">
  ISO 8601 timestamp of when the call connected.
</ResponseField>

<ResponseField name="ended_at" type="string">
  ISO 8601 timestamp of when the call ended.
</ResponseField>

## Call cost breakdown

Every call has a cost composed of three components:

| Component | Field | Driver |
|-----------|-------|--------|
| LLM (input) | `tokens_input` | Prompt size, conversation length, tool results |
| LLM (output) | `tokens_output` | Agent response length |
| Speech-to-text | `stt_duration_seconds` | Audio duration of prospect speech |
| Text-to-speech | `tts_characters` | Character count of agent responses |

The `cost_usd` field reflects the sum of all components using your plan's per-unit rates. Use the detailed fields (`tokens_input`, `tokens_output`, `tts_characters`, `stt_duration_seconds`) to identify cost drivers and optimize your prompt templates or agent configuration.

**Tips to reduce cost:**

- Shorten your system prompt - `tokens_input` is charged per turn
- Lower `max_tokens` in your LLM config to limit response verbosity
- Use a faster STT model for shorter `endpointing_ms` (reduces STT duration slightly)
- Switch to a lower-cost LLM for simpler use cases (e.g. `gpt-4o-mini`)

## Getting the recording URL

The `recording_url` field is a presigned URL available a few seconds after the call ends. It expires after 24 hours.

```python Python
call = requests.get(
    f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/calls/{call_id}",
    headers={"X-API-Key": API_KEY},
).json()

recording_url = call.get("recording_url")
if recording_url:
    # Download and store in your own storage
    audio = requests.get(recording_url).content
    with open(f"{call_id}.mp3", "wb") as f:
        f.write(audio)
```

<Warning>
  Recording URLs expire after 24 hours. If you need long-term access to recordings, download them to your own storage (S3, GCS, etc.) immediately after the `call.completed` webhook fires.
</Warning>

## Pagination patterns

To process all calls for a date range or status, paginate using `page` and `size`:

```python Python
def iter_calls(status=None, started_after=None, started_before=None):
    """Generator that yields all calls matching the given filters."""
    page = 1
    while True:
        params = {"page": page, "size": 100}
        if status:
            params["status"] = status
        if started_after:
            params["started_after"] = started_after
        if started_before:
            params["started_before"] = started_before

        resp = requests.get(
            f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/calls",
            headers={"X-API-Key": API_KEY},
            params=params,
        ).json()

        yield from resp["data"]
        meta = resp["meta"]
        if meta["page"] >= meta["total_pages"]:
            break
        page += 1

import csv, io

buf = io.StringIO()
```

## Webhook vs polling

| Approach | Best for | Tradeoffs |
|----------|----------|-----------|
| **Webhooks** | Production use, real-time processing | Requires a public HTTPS endpoint; handle retries and deduplication |
| **Polling** | Development, batch processing, ad-hoc scripts | Simple to implement; latency proportional to poll interval; wastes API quota |

For production integrations, use webhooks. Configure your endpoint in [Dashboard - Webhook Settings](https://dash.prod.czmx.in) and refer to the [Webhooks](/webhooks) reference for payload details.

For local development, use the [Cozmo CLI](/cli/webhook) to forward webhook events to your local machine.
