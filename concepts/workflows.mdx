## What is a workflow?

A workflow is a named, versioned execution template that governs an agent interaction from start to finish. Configured in the Cozmo AI Dashboard, a workflow defines:

- Which agent handles the interaction
- How and when calls are placed (trigger type, scheduling rules, calling hours)
- Retry logic for unanswered calls
- Post-call evaluation outcomes to extract
- Escalation rules and follow-up sequences

Via the Nova API you can:

- **List and retrieve** workflows to reference them in your integrations
- **Create workflow runs** to trigger a workflow for a specific prospect
- **Schedule runs** for a future time
- **Pass custom_data** to give the agent prospect-specific context

<Info>
  Workflows are created and configured in the Dashboard, not via the API. The API is used to trigger runs against existing workflows.
</Info>

## Workflow fields

<ResponseField name="id" type="string">
  Unique workflow identifier (e.g. `wf_abc123`).
</ResponseField>

<ResponseField name="name" type="string">
  Human-readable name for the workflow.
</ResponseField>

<ResponseField name="description" type="string">
  Description of what the workflow does and which prospects it targets.
</ResponseField>

<ResponseField name="is_active" type="boolean">
  Whether the workflow is currently active. Inactive workflows do not accept new runs. Always filter by `is_active=true` in production integrations.
</ResponseField>

<ResponseField name="trigger_type" type="string">
  How the workflow is initiated. See [Trigger types](#trigger-types) below.
</ResponseField>

<ResponseField name="version" type="integer">
  Current version number. Increments each time the workflow definition is updated in the Dashboard. Use this to detect configuration changes.
</ResponseField>

<ResponseField name="published_at" type="string">
  ISO 8601 timestamp of when the current version was published.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the workflow was first created.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the last update to the workflow.
</ResponseField>

## Trigger types

| Trigger type | Description | How to start |
|-------------|-------------|--------------|
| `api` | Triggered programmatically via the Create Workflow Run endpoint | POST to `/workflow-runs` |
| `schedule` | Triggered automatically on a cron schedule | Configured in Dashboard |
| `inbound` | Triggered when an inbound call is received on a configured number | Automatic on call receipt |

For API integrations, always use `trigger_type: api` workflows. `schedule` and `inbound` workflows run automatically and do not accept API-triggered runs.

## Listing workflows

Retrieve all workflows in your organization:

<CodeGroup>

```bash cURL
# All active API-triggered workflows
curl "https://v2-nova-api.prod.czmx.in/api/org/{org_id}/workflows?is_active=true&trigger_type=api" \
  -H "X-API-Key: YOUR_API_KEY"

# All workflows (including inactive)
curl "https://v2-nova-api.prod.czmx.in/api/org/{org_id}/workflows" \
  -H "X-API-Key: YOUR_API_KEY"

# Search by name
curl "https://v2-nova-api.prod.czmx.in/api/org/{org_id}/workflows?search=outbound+sales" \
  -H "X-API-Key: YOUR_API_KEY"
```

```python Python
import requests
import os

ORG_ID = os.environ["ORG_ID"]
API_KEY = os.environ["NOVA_API_KEY"]

# Get all active API workflows
response = requests.get(
    f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/workflows",
    headers={"X-API-Key": API_KEY},
    params={"is_active": True, "trigger_type": "api", "page": 1, "size": 20},
)
response.raise_for_status()
data = response.json()

for wf in data["data"]:
    print(f"{wf['id']}  {wf['name']}  v{wf['version']}  active={wf['is_active']}")

print(f"\nTotal: {data['meta']['total']} workflows")
```

```go Go
package main

import (
    "encoding/json"
    "fmt"
    "net/http"
    "os"
)

type Workflow struct {
    ID          string `json:"id"`
    Name        string `json:"name"`
    Description string `json:"description"`
    IsActive    bool   `json:"is_active"`
    TriggerType string `json:"trigger_type"`
    Version     int    `json:"version"`
    PublishedAt string `json:"published_at"`
}

func ListWorkflows(orgID string) ([]Workflow, error) {
    url := fmt.Sprintf(
        "https://v2-nova-api.prod.czmx.in/api/org/%s/workflows?is_active=true&trigger_type=api",
        orgID,
    )
    req, _ := http.NewRequest("GET", url, nil)
    req.Header.Set("X-API-Key", os.Getenv("NOVA_API_KEY"))

    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return nil, fmt.Errorf("listing workflows: %w", err)
    }
    defer resp.Body.Close()

    var result struct {
        Data []Workflow `json:"data"`
    }
    if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
        return nil, fmt.Errorf("decoding response: %w", err)
    }
    return result.Data, nil
}
```

## Creating a workflow run

A workflow run triggers a workflow for a specific prospect. If a prospect with the same `external_id` already exists in your org, it is matched - otherwise a new prospect record is created.

<CodeGroup>

```bash cURL
curl -X POST https://v2-nova-api.prod.czmx.in/api/org/{org_id}/workflow-runs \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "workflow_id": "wf_abc123",
    "prospect": {
      "phone": "+19175551234",
      "first_name": "Jane",
      "last_name": "Doe",
      "email": "jane.doe@example.com",
      "external_id": "crm_contact_789",
      "country": "US",
      "timezone": "America/New_York",
      "custom_data": {
        "demo_requested_at": "2026-04-15",
        "product_interest": "Enterprise Plan",
        "company": "Acme Corp",
        "deal_value_usd": 48000,
        "previous_calls": 2
      }
    }
  }'
```

```go Go
type ProspectData struct {
    Phone      string                 `json:"phone"`
    FirstName  string                 `json:"first_name"`
    LastName   string                 `json:"last_name"`
    Email      string                 `json:"email"`
    ExternalID string                 `json:"external_id"`
    Country    string                 `json:"country,omitempty"`
    Timezone   string                 `json:"timezone,omitempty"`
    CustomData map[string]interface{} `json:"custom_data,omitempty"`
}

type CreateRunRequest struct {
    WorkflowID  string       `json:"workflow_id"`
    Prospect    ProspectData `json:"prospect"`
    ScheduledAt string       `json:"scheduled_at,omitempty"`
}

func CreateWorkflowRun(orgID string, req CreateRunRequest) (string, error) {
    body, _ := json.Marshal(req)
    httpReq, _ := http.NewRequest("POST",
        fmt.Sprintf("https://v2-nova-api.prod.czmx.in/api/org/%s/workflow-runs", orgID),
        bytes.NewReader(body),
    )
    httpReq.Header.Set("X-API-Key", os.Getenv("NOVA_API_KEY"))
    httpReq.Header.Set("Content-Type", "application/json")

    resp, err := http.DefaultClient.Do(httpReq)
    if err != nil {
        return "", fmt.Errorf("creating workflow run: %w", err)
    }
    defer resp.Body.Close()

    var result struct {
        WorkflowRunID string `json:"workflow_run_id"`
    }
    json.NewDecoder(resp.Body).Decode(&result)
    return result.WorkflowRunID, nil
}
```

### Run request fields

<ResponseField name="workflow_id" type="string" required>
  ID of the workflow to run.
</ResponseField>

<ResponseField name="prospect" type="object" required>
  Prospect to run the workflow against. If a prospect with the same `external_id` already exists in your org, it is matched; otherwise a new prospect record is created.
  <Expandable title="prospect fields">
    <ResponseField name="phone" type="string" required>
      Phone number in E.164 format (e.g. `+19175551234`).
    </ResponseField>
    <ResponseField name="first_name" type="string">
      Prospect's first name. Available as `{{prospect_name}}` in the agent's prompt template.
    </ResponseField>
    <ResponseField name="last_name" type="string" />
    <ResponseField name="email" type="string" />
    <ResponseField name="external_id" type="string">
      Your CRM or internal ID for this contact. Used to deduplicate prospects - if a prospect with this ID exists, the run is linked to the existing prospect record rather than creating a new one.
    </ResponseField>
    <ResponseField name="country" type="string">
      ISO 3166-1 alpha-2 country code (e.g. `US`, `GB`, `AE`). Used to determine calling hours compliance.
    </ResponseField>
    <ResponseField name="timezone" type="string">
      IANA timezone string (e.g. `America/New_York`, `Europe/London`). Used with calling hours rules to schedule calls at appropriate local times.
    </ResponseField>
    <ResponseField name="custom_data" type="object">
      Arbitrary JSON metadata available to the agent during the workflow run. Use this to pass deal context, previous interaction history, product interests, or any other information the agent should know.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="scheduled_at" type="string">
  ISO 8601 datetime (UTC) to schedule the run. If omitted, the run starts immediately according to your workflow's calling hour rules.
</ResponseField>

## Scheduled runs

Use `scheduled_at` to trigger a run at a specific future time rather than immediately:

<CodeGroup>

```python Python
from datetime import datetime, timezone, timedelta

# Schedule for tomorrow at 10 AM UTC
tomorrow_10am = datetime.now(timezone.utc).replace(
    hour=10, minute=0, second=0, microsecond=0
) + timedelta(days=1)

response = requests.post(
    f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/workflow-runs",
    headers={"X-API-Key": API_KEY},
    json={
        "workflow_id": "wf_abc123",
        "scheduled_at": tomorrow_10am.isoformat(),
        "prospect": {
            "phone": "+19175551234",
            "first_name": "Jane",
            "external_id": "crm_789",
            "timezone": "America/New_York",
        },
    },
)
print("Scheduled run:", response.json()["workflow_run_id"])
```

```typescript TypeScript
// Schedule for a specific time - convert to UTC ISO string
const scheduledAt = new Date("2026-04-22T14:00:00-05:00").toISOString(); // 2 PM CDT

const response = await fetch(
  `https://v2-nova-api.prod.czmx.in/api/org/${ORG_ID}/workflow-runs`,
  {
    method: "POST",
    headers: { "X-API-Key": API_KEY, "Content-Type": "application/json" },
    body: JSON.stringify({
      workflow_id: "wf_abc123",
      scheduled_at: scheduledAt,
      prospect: {
        phone: "+19175551234",
        first_name: "Jane",
        external_id: "crm_789",
        timezone: "America/Chicago",
      },
    }),
  }
);
```

</CodeGroup>

<Info>
  Always pass `scheduled_at` in UTC. Pass the prospect's `timezone` so Nova can apply calling hours rules correctly - the call fires at whichever is later: your `scheduled_at` time or the next valid calling hour window.
</Info>

## custom_data in workflow context

The `custom_data` object you pass in the prospect payload is available to the agent during the call. In your agent's prompt template, you can reference custom data via template variables or by instructing the agent to use it from context.

**Example prompt template using custom_data:**

```
You are an outbound sales agent for Acme Corp.
You are calling {{prospect_name}} to follow up on their enterprise software inquiry.

Key details about this prospect:
- Company: {{custom_data.company}}
- Product interest: {{custom_data.product_interest}}
- Demo requested on: {{custom_data.demo_requested_at}}
- Estimated deal value: ${{custom_data.deal_value_usd}}

Goal: Schedule a product demo call with the decision maker.
```

Pass rich context in `custom_data` - the more relevant detail you provide, the more personalized and effective the agent's conversation.

## Prospect deduplication

When you create a workflow run, pass `external_id` in the prospect object. This is your CRM or internal contact identifier. Nova uses it for deduplication:

- If a prospect with this `external_id` already exists in your org, the run is linked to the existing prospect record
- If no match is found, a new prospect record is created

This means you can safely trigger workflow runs without checking whether a prospect already exists:

```python Python
# Safe to call multiple times for the same contact - will not create duplicates
def enqueue_outreach(crm_contact: dict):
    return requests.post(
        f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/workflow-runs",
        headers={"X-API-Key": API_KEY},
        json={
            "workflow_id": "wf_abc123",
            "prospect": {
                "phone": crm_contact["phone"],
                "first_name": crm_contact["first_name"],
                "last_name": crm_contact["last_name"],
                "email": crm_contact["email"],
                "external_id": crm_contact["id"],  # Your CRM ID - deduplicates prospect
                "custom_data": {
                    "deal_stage": crm_contact["deal_stage"],
                    "deal_value": crm_contact["deal_value"],
                },
            },
        },
    ).json()
```

## Workflow run lifecycle

Runs move through the following states:

| Status | Description |
|--------|-------------|
| `pending` | Run created; waiting to be processed or for `scheduled_at` to arrive |
| `active` | Call is in progress |
| `completed` | Workflow run finished - call completed, analysis done |
| `failed` | Run encountered an error (call failed, validation error) |
| `cancelled` | Run was cancelled before the call connected |

Use the `call.completed` and `call.failed` webhook events to react to run outcomes. The webhook payload includes `call_result`, `evaluations`, `summary`, and `transcript`.

## Bulk calling patterns

To trigger many workflow runs efficiently, batch your API calls and stay within rate limits.

<Warning>
  The Nova API enforces a rate limit of 1,000 requests per minute for standard endpoints. When triggering bulk runs, use controlled concurrency and respect the limits.
</Warning>

```python Python
import asyncio
import aiohttp
import time
from typing import List

async def trigger_bulk_runs(
    workflow_id: str,
    prospects: List[dict],
    concurrency: int = 10,
    delay_between_batches: float = 0.1,
) -> List[str]:
    """Trigger workflow runs for a list of prospects with controlled concurrency."""
    run_ids = []
    semaphore = asyncio.Semaphore(concurrency)

    async def trigger_one(session: aiohttp.ClientSession, prospect: dict) -> str:
        async with semaphore:
            async with session.post(
                f"https://v2-nova-api.prod.czmx.in/api/org/{ORG_ID}/workflow-runs",
                headers={"X-API-Key": API_KEY},
                json={"workflow_id": workflow_id, "prospect": prospect},
            ) as resp:
                if resp.status == 429:
                    # Rate limited - wait and retry
                    reset = int(resp.headers.get("X-Rate-Limit-Reset", time.time() + 60))
                    await asyncio.sleep(max(reset - time.time(), 1))
                    return await trigger_one(session, prospect)
                resp.raise_for_status()
                data = await resp.json()
                return data["workflow_run_id"]

    async with aiohttp.ClientSession() as session:
        tasks = [trigger_one(session, p) for p in prospects]
        results = await asyncio.gather(*tasks, return_exceptions=True)

    for i, result in enumerate(results):
        if isinstance(result, Exception):
            print(f"Failed for prospect {prospects[i].get('external_id')}: {result}")
        else:
            run_ids.append(result)

    return run_ids

# Usage: trigger 500 calls
prospects = [
    {"phone": f"+1917555{str(i).zfill(4)}", "external_id": f"crm_{i}"}
    for i in range(500)
]

run_ids = asyncio.run(trigger_bulk_runs("wf_abc123", prospects, concurrency=10))
print(f"Triggered {len(run_ids)} runs")
```

**Rate limit guidance for bulk operations:**

- Use a concurrency of 5-10 simultaneous requests to stay well within limits
- Add a small delay between batches if you are triggering hundreds of runs
- Monitor `X-Rate-Limit-Remaining` and back off when it drops below 100
- For very large batches (10,000+), spread requests over several minutes using a queue
