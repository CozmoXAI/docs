## Prerequisites

- [VSCode](https://code.visualstudio.com) 1.99 or later with the [GitHub Copilot extension](https://marketplace.visualstudio.com/items?itemName=GitHub.copilot) installed
- Node.js 18 or later
- A Cozmo API key from [Dashboard → Organization Settings](https://dash.prod.czmx.in)

## Step 1 - Install the MCP server

```bash
npm install -g @cozmoai/mcp-server
```

## Step 2 - Configure VSCode

Create a `.vscode/mcp.json` file at the root of your project:

```bash
mkdir -p .vscode
```

```json .vscode/mcp.json
{
  "servers": {
    "cozmo-nova": {
      "command": "npx",
      "args": ["@cozmoai/mcp-server"],
      "env": {
        "COZMO_API_KEY": "YOUR_API_KEY",
        "COZMO_ORG_ID": "YOUR_ORG_ID"
      }
    }
  }
}
```

<Warning>
  Do not commit API keys to version control. For shared workspaces, omit the `env` block and set `COZMO_API_KEY` in each developer's shell environment.
</Warning>

**Team-safe version** - commit this, have each developer export their own key:

```json .vscode/mcp.json
{
  "servers": {
    "cozmo-nova": {
      "command": "npx",
      "args": ["@cozmoai/mcp-server"]
    }
  }
}
```

Each developer exports in their shell:

```bash
export COZMO_API_KEY="your_api_key"
export COZMO_ORG_ID="your_org_id"
```

## Step 3 - Reload VSCode

Run **Developer: Reload Window** from the command palette (`⇧⌘P` / `Ctrl+Shift+P`). GitHub Copilot will pick up the MCP server on reload.

## Step 4 - Verify

Open Copilot Chat (`⇧⌘I` / `Ctrl+Shift+I`) and ask:

> *"What does the Nova API's `call.completed` webhook payload look like?"*

A correct answer will include the `data.call_id`, `data.call_result`, `data.evaluations`, `data.transcript`, `data.recording_url`, and nested `data.prospect` fields - all from Cozmo's actual webhook schema.

## Using Copilot Chat with Nova API context

With the MCP server active, Copilot Chat has access to the full Nova API knowledge. Ask questions directly:

```
How do I create a voice agent with a Deepgram transcriber and GPT-4o?
```

```
Write a TypeScript function to start a session for an existing prospect
```

```
What HTTP status codes does the Nova API return and when?
```

You can also use it inline while editing - Copilot will automatically use MCP context when completing Nova API code.

<AccordionGroup>

    > *"Scaffold an Express.js webhook handler for all four Cozmo events: call.completed, call.failed, session.completed, session.failed"*

  </Accordion>

  <Accordion title="Paginated call listing">
    > *"Write a function that fetches all calls for my org, handling pagination automatically"*

    Copilot will use `GET /org/{org_id}/calls` with `page` and `size` params, looping through `meta.total_pages` until all records are fetched.
  </Accordion>

## Troubleshooting

<AccordionGroup>
  <Accordion title="MCP server not showing in Copilot">
    Check that the Copilot extension is up to date - MCP support requires VSCode 1.99 or later. Update via the VSCode Extensions panel.

    Then verify `.vscode/mcp.json` is in the **root of the open workspace folder**, not inside a subdirectory.

    Reload the window after any config changes:

    ```
    ⇧⌘P → Developer: Reload Window
    ```
  </Accordion>

  <Accordion title="npx not found when VSCode launches">
    VSCode may not inherit your shell's PATH. Set the full path to npx in the config:

    ```bash
    which npx   # e.g. /Users/you/.nvm/versions/node/v18.20.0/bin/npx
    ```

    Then use the full path:

    ```json
    {
      "servers": {
        "cozmo-nova": {
          "command": "/Users/you/.nvm/versions/node/v18.20.0/bin/npx",
          "args": ["@cozmoai/mcp-server"]
        }
      }
    }
    ```
  </Accordion>

  <Accordion title="Copilot still generating wrong API calls">
    Make sure `.vscode/mcp.json` is at the root of the open workspace. Copilot MCP context is workspace-scoped.

    Reload the window after any changes to the config file, then start a fresh Copilot Chat session.
  </Accordion>

  <Accordion title="Environment variables not picked up">
    If you set `COZMO_API_KEY` in your shell profile but VSCode doesn't see it, add the `env` block explicitly to `.vscode/mcp.json` for local development and add the file to `.gitignore`.
  </Accordion>
</AccordionGroup>
